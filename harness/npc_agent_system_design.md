## 一、系统总览

### 1.1 设计目标

让 AI 角色具备**灵魂感**（主体性 + 进化）：
- **有故事**：编剧 Agent 推动剧情，角色活在故事里
- **有主体**：角色通过自主推理和反思做出决策，有能力偏离编剧安排的轨道
- **有进化**：角色的情感、关系、认知随经历持续变化

### 1.2 两大场景

| 场景 | 核心模块 | 做什么 | 参考方案 |
|------|---------|--------|---------|
| **LBS 世界模拟** | 灵魂 Agent | 角色在世界里生活：感知→检索→推理→反思→执行 | 斯坦福小镇论文 |
| **聊天互动**（故事/日常） | Deep Feeling | 角色与用户对话：意图→模式路由→推理→反思→回复 | prompt-engineering/deep_feeling |

**灵魂 Agent（LBS）和 Deep Feeling（聊天）是不同场景下的不同模块，不混用。**

### 1.3 核心组件

| 组件 | 角色 | 类比 |
|------|------|------|
| 时钟 | 驱动一切的心跳 | 时间 |
| X Agent | 世界氛围发生器，输出虚态事件（氛围/运势/趋势） | 大运流年 / 自然法则 |
| 编剧 Agent | 事件执行中枢，将氛围演绎为具体事件 + 角色日程 + 剧情指令 | 编剧 / 导演 |
| 世界模拟 Agent | 物理引擎，维护物品状态，item 绑定发布 | 物理世界 |
| 灵魂 Agent | 在 LBS 世界中感知、推理、反思、行动的主体 | 人 |
| Deep Feeling | 聊天场景下的情感推理引擎（故事模式 + 日常陪伴模式） | 灵魂 |

### 1.4 系统拓扑图

> 在线查看（含连线可视化）：[Livo Agent 系统拓扑图](https://aigc-image-1253543992.cos.ap-beijing.myqcloud.com/architecture/npc_agent_topology_20260415_114920.html)

```
  时钟 ──tick──→ X Agent ──氛围信号(虚态)──→ 编剧 ──events(实态)──→ 世界模拟 ──event_info──→ 角色
    │                                    │                        ↑                     ↑↓
    └──tick──────────────────────────→ 世界模拟              角色行为结果              reply
                                        ↑                  用户操作                    ↓
                                        │                                            用户
                                   world_state ──→ 编剧
                                   编剧 ──plot_directive──→ 角色
```

**关键变化（对齐会确认）：X Agent不再直连世界模拟，X Agent只输出虚态氛围信号给编剧，由编剧统一演绎为实态事件。**

### 1.5 完整数据流清单

| # | 从 | 到 | 数据 | 说明 |
|---|----|----|------|------|
| 1 | 时钟 | X Agent | `tick` `current_time` | 驱动X Agent演进 |
| 2 | 时钟 | 世界模拟 | `tick` `current_time` | 驱动机械更新（课表、作息） |
| 3 | X Agent | 编剧 | `atmosphere` | 虚态事件：世界氛围/运势/情绪趋势 |
| 4 | 编剧 | 世界模拟 | `common_events[]` `persona_events[]` | 所有实态事件统一由编剧产出 |
| 5 | 编剧 | 角色 | `plot_directive` | 剧情指令 + 角色日程安排 |
| 6 | 世界模拟 | 编剧 | `world_state` | 当前物品状态，编剧决策依据 |
| 7 | 世界模拟 | 角色 | `event_info[]` | 按角色 item tree 过滤，item 绑定发布 |
| 8 | 角色 | 世界模拟 | `action_results[]` | 行为导致的物品状态变更 |
| 9 | 角色 | 编剧 | `character_state` | 情感/关系/位置/成长 |
| 10 | 用户 | 世界模拟 | `user_input` | 用户直接操作世界 |
| 11 | 用户 | 角色 | `user_message` | 用户跟角色聊天 |
| 12 | 角色 | 用户 | `reply` | 角色回复用户 |

### 1.6 虚态事件 vs 实态事件（对齐会核心结论）

| | 虚态事件 | 实态事件 |
|---|---------|---------|
| 产出者 | X Agent | 编剧 Agent |
| 性质 | 氛围、趋势、运势，不指向具体动作 | 具体行为变更，驱动世界状态变化 |
| 举例 | "今日全城悲伤氛围" | "物理课改体育课" |
| 下游 | → 编剧（作为演绎素材） | → 世界模拟（更新物品状态） |
| 是否改变世界状态 | **否** | **是** |

## 二、各 Agent 详细设计

### 2.1 X Agent

**定位：世界氛围发生器。** 独立运行，只输出虚态信号，**不直接修改世界状态**。

```
  tick ────────→┌──────────────┐
  current_time ─→│  X Agent   │
                │  (大运流年)    │
                │              │
                │ 内部：        │
                │ · 运势轮转    │
                │ · 情绪场     │
                │ · 氛围趋势   │
                └──────┬───────┘
                       │
                       ▼
                  atmosphere
                (虚态氛围信号)
                       │
                       ▼
                     编剧
              (由编剧演绎为实态事件)
```

**atmosphere 示例：**
```json
{
  "current_phase": "篮球联赛备战期",
  "world_mood": "紧张、竞争",
  "season": "晚春、多雨",
  "fortune_hint": "今日偏动荡，易生口角",
  "active_trends": ["校际篮球联赛下周开始", "期中考试临近"]
}
```

### 2.2 编剧 Agent

**定位：事件执行中枢。** 接收X Agent氛围 + 世界/角色状态，统一产出所有实态事件。

```
  X Agent.atmosphere ───→┐
  world_state ──────→│
  character_states ─→│  编剧 Agent
  user_behavior ────→│  (事件执行中枢)
  plot_progress ────→│
  story_config ─────→│
                     └───┬──────────────┬────────────┐
                         ▼              ▼            ▼
                  common_events    persona_events   plot_directive
                  (世界级实态事件)  (角色相关实态事件) (剧情指令+日程)
                     ↓                ↓               ↓
                  世界模拟          世界模拟           角色
```

**编剧如何演绎X Agent氛围：**
```
X Agent输出："今日全城悲伤氛围"
编剧演绎：
  · common_event: "学校广播播放了一首悲伤的音乐"
  · persona_event: "钟辰时收到了一条让他难过的消息"
  · 日程微调: 取消原定的户外活动
```

**plot_directive 包含两类内容：**
1. **日程安排**（默认轨道）：角色今天的日程表，角色可以基于推理偏离
2. **剧情事件**：接下来要发生的剧情内容，角色通过感知获取

**两种模式的差异：**

| | 故事模式 | 日常陪伴模式 |
|---|---------|-----------|
| 世界观 | 角色的世界（南一高中） | 用户的真实世界 |
| 编剧产出 | 推动角色世界故事线的事件 | 角色"那边"发生了什么 |
| 用户角色 | 用户是世界中的参与者 | 用户是"另一个世界的人" |
| 交互方式 | 角色与用户在同一场景 | 聊天、打电话、发消息（异步） |

### 2.3 世界模拟 Agent

**定位：物理引擎 + item 绑定发布。** 不产出事件，只处理状态更新和分发通知。

```
  编剧.common_events[] ───→┐
  编剧.persona_events[] ──→│  世界模拟 Agent
  tick + current_time ─────→│  (物理引擎)
  角色.action_results[] ──→│
  用户.user_input ─────────→│
                            │
                    ┌───────┴────────┐
                    │  全量物品状态树  │
                    │ (item 绑定发布) │
                    └───────┬────────┘
                            │
                 ┌──────────┴──────────┐
                 ▼                     ▼
            world_state           event_info[]
            (世界状态快照)         (按角色 item tree
               ↓                  过滤后分发)
              编剧                    ↓
                                    角色
```

**对齐会确认的设计要点：**
- **item 绑定发布**：不单独维护 message bus，事件通知绑定在 item 上
- **天气作为全局 item**：所有角色同步感知
- **event_info 只记录最新状态**，不含 old_state

**event_info 结构（对齐会修订）：**
```json
{
  "item": "南一高中:教学楼:高二三班教室:钟辰时的书桌",
  "state": "课本散落一地，椅子倒了",
  "cause": "周往路过时不小心撞到",
  "time": "2026-04-15 10:15",
  "related_personas": ["钟辰时", "周往"]
}
```

**全量物品状态树示例：**
```json
{
  "南一高中": {
    "教学楼": {
      "高二三班教室": {
        "钟辰时的书桌": { "state": "整齐摆放着课本和笔记", "owner": "钟辰时" },
        "黑板": { "state": "写着今天的值日表", "owner": null }
      }
    },
    "全局": {
      "天气": { "state": "多云转小雨", "owner": null }
    }
  }
}
```

### 2.4 灵魂 Agent（LBS 世界模拟）

在 LBS 世界中感知、推理、反思、行动的主体。参考斯坦福小镇论文的认知循环。详见第三章。

```
  event_info[] ────→┐
  plot_directive ──→│  灵魂 Agent (LBS)
                    │
                    │  ┌────────────────────────────────┐
                    │  │ 感知 → 记忆检索 → 推理 → 反思    │
                    │  │            ↓                    │
                    │  │  按日程执行 or 偏离（主体性）       │
                    │  └────────────────────────────────┘
                    │
              ┌─────┴─────┐
              ▼           ▼
       action_results  character_state
         → 世界模拟      → 编剧
```

### 2.5 Deep Feeling（聊天场景）

聊天互动时的情感推理引擎，包括故事模式和日常陪伴模式。与灵魂 Agent 分属不同场景。

```
  user_message ────→┐
  角色记忆/情绪 ────→│  Deep Feeling
  角色人设 ─────────→│  (聊天情感推理)
                    │
                    │  intent_skill → mode_skill(S/B/D) → 信息装载
                    │       → reasoning → reflection(仅Deep)
                    │
                    └──────┬──────┐
                           ▼      ▼
                        reply   emotion_update
                        → 用户   → 角色状态
```

**三种模式：**

| 模式 | 触发条件 | 做什么 | 占比 |
|------|---------|--------|------|
| **Short** | 日常琐事 | 不推理，直出回复 | ~80% |
| **Brief** | 轻微触动 | 简短推理，一行内心 | ~15% |
| **Deep** | 强烈冲击 | 完整推理+反思+多方案权衡 | ~5% |

> Deep Feeling 完整方案见 `prompt-engineering/deep_feeling/deep_feeling_architecture.md`

## 三、灵魂 Agent 内部架构（LBS 世界模拟）

### 3.1 设计原则

1. **角色是"活人"**：主动感知环境，不是被动接收通知
2. **参考斯坦福小镇的认知循环**：感知→检索→推理→反思→执行
3. **记忆和情绪是两套独立系统**：记忆 = 经历了什么；情绪 = 当下的感受（VAD）
4. **编剧给默认轨道，角色保留主体性**：日程由编剧安排，角色可以基于推理和反思偏离
5. **偏离 = 主体性的体现**：灵魂感 = 主体性 + 进化

### 3.2 感知机制（对齐会确认）

**坐标感知：** 第一版采用坐标感知机制，角色仅能感知当前位置邻近物品的实时变化。

**认知状态树：** 每个角色拥有专属认知状态树（= item tree），初始仅知晓自身周围环境。认知范围随交互逐步扩展。

**关键规则：**
- 离开区域后，**不再自动同步**该区域的状态变更
- 回归时获取最新状态，**不追溯中间过程**
- 通过与其他角色交流可获取未知区域信息（认知扩展）

### 3.3 内部流程（参考斯坦福小镇）

```
  感知到的所有信息
  (坐标邻近的 item 状态变化 + 日程 + 其他角色)
         │
         ▼
  ┌──────────────────────────────────┐
  │  记忆 Memory  │◄─互相影响─►│ 情绪 VAD │
  └──────┬────────┘            └────┬─────┘
         │                         │
         ▼                         │
    记忆检索                        │
    (recency + importance          │
     + relevance 三维加权)          │
         │                         │
         └────────────┬────────────┘
                      ▼
                    推理
              综合记忆+情绪+感知
              判断当前情况和行为意图
                      │
                      ▼
                    反思
              对重要事件生成高阶洞察
              (重要性累计超阈值时触发)
                      │
                      ▼
                    决策
              按日程执行 or 偏离？
              (偏离 = 主体性)
                      │
                      ▼
                    执行
          ┌─────────┴─────────┐
          ▼                   ▼
   action_results        char_state
     → 世界模拟             → 编剧
```

### 3.4 每 tick 循环

```
每个 tick：

1. 感知（Perceive）
   坐标感知：扫描当前位置邻近 item 的状态变化
   同时获取：日程、其他角色的行为

2. 记忆 + 情绪更新
   感知内容写入记忆流（观察类记忆）
   同步更新 VAD 情绪状态

3. 记忆检索（Retrieve）
   以当前感知为 Query，三维加权检索相关记忆
   recency + importance + relevance

4. 推理（Reason）
   综合感知 + 检索到的记忆 + 当前情绪
   判断当前情况，形成行为意图

5. 反思（Reflect）
   近期记忆重要性累计超阈值时触发
   生成高阶洞察，写入记忆流

6. 决策 + 执行
   按日程执行 or 偏离
   产出 action_results / character_state
```

### 3.5 与斯坦福小镇论文的关键差异

| 环节 | 论文（斯坦福小镇） | 我们的设计 |
|------|-----------------|----------|
| 感知 | pull，扫描附近 tile 的 events | **坐标感知**，离开不同步，回归刷新，不追溯中间过程 |
| 记忆 | 记忆流是唯一系统 | **记忆流 + VAD 情绪系统**，两套独立 |
| 检索 | 三维加权检索 | **保留**，与论文一致 |
| 推理 | LLM 推理 | **保留** |
| 反思 | 重要性>150 触发，生成高阶洞察 | **保留**，参考论文机制 |
| 规划 | 角色自主三级规划（粗→小时→执行级） | **日程由编剧安排**，角色感知日程作为默认轨道 |
| 主体性 | 完全自主（但缺乏叙事控制） | **编剧给轨道 + 角色可偏离**，偏离由推理和反思驱动 |

### 3.6 记忆系统（参考论文）

**单条记忆 8 字段（与论文一致）：** 记忆ID、自然语言描述、类型（观察/反思/计划）、创建时间戳、最近访问时间戳、重要性分数（1-10）、引用指针列表、嵌入向量

**三维检索：** Final Score = Normalized(Recency) + Normalized(Importance) + Normalized(Relevance)

### 3.7 情绪系统（新增）

独立于记忆，用 **VAD 模型**表示角色当下情绪：V(愉悦度) / A(激活度) / D(支配感)，范围 -1~1。感知时同步更新，随时间自然衰减回基线。

### 3.8 角色 Item Tree（= 认知状态树）

每个角色的认知子集，初始仅包含角色知晓的区域。世界模拟据此过滤 event_info。可通过感知和交流动态扩展。

```json
{
  "南一高中": {
    "教学楼": {
      "高二三班教室": ["钟辰时的书桌", "黑板", "讲台"],
      "学生会办公室": ["会议桌", "文件柜", "钟辰时的储物格"]
    },
    "图书馆": { "阅览室": ["靠窗的老位置"] }
  }
}
```

### 3.9 角色间互动机制

当两个角色的日程在同一时间同一地点重合时，可能触发互动。

**互动流程：**

```
  世界模拟检测到 A、B 在同一地点
         │
         ▼
  通知双方："对方也在这里"（作为 event_info 推送）
         │
         ▼
  世界模拟指定先手方（随机或按规则）
         │
         ▼
  先手方 A 推理：要不要跟 B 互动？
  (基于关系、当前活动、记忆检索)
         │
    不互动 → 各做各的（大部分情况）
    互动   ↓
         │
         ▼
  A 生成第一句话 → 写入 A 记忆流
         │
         ▼
  B 感知 A 说的话 → 写入 B 记忆流
  B 推理生成回应 → 写入 B 记忆流
         │
         ▼
  轮转（A一句 B一句），直到结束
         │
         ▼
  对话结束，双方各自更新：
  · 完整对话 → 写入双方记忆流
  · VAD → 双方各自更新
  · 日程 → 任一方可能偏离
```

**对话结束条件：**
- 达到最大轮次（5-10 轮）
- 一方推理判断"该走了"（日程有别的事、话题结束）
- 外部事件打断（上课铃响了）

**互动判断参考斯坦福小镇的 `_should_react`：**
- 跟对方的关系（熟悉度、亲密度）
- 自己当前在干什么（上课中不太会主动搭话）
- 记忆检索（上次聊了什么、有没有未完成的约定）

### 3.10 推理 + 偏离决策示例

**日常场景 — 按日程执行**
```
感知：上课铃响了（日程）
检索：无特殊相关记忆
推理：正常上课，没有异常
决策：按日程去上课
```

**突发场景 — 偏离日程**
```
感知：周往在操场受伤了（event_info）
检索：上周周往也扭过脚 + 关系：好友，亲密度 65
推理：他可能伤得不轻，我应该过去看看
反思：我一直说要多关心朋友，这次不能只是想想
决策：偏离日程，去操场（偏离 = 主体性）

action_results：钟辰时离开教室前往操场
character_state：位置变更 + VAD 变化(V↓ A↑ D↓) → 反馈给编剧
```

## 附录：对齐会决策记录

**2026-04-15 系统设计对齐会**

| 决策项 | 结论 |
|--------|------|
| X Agent vs 编剧职责 | X Agent = 世界氛围发生器（虚态），编剧 = 事件执行中枢（实态） |
| X Agent是否直连世界模拟 | **否**，X Agent只连编剧，由编剧统一演绎为实态事件 |
| 统一入口 | 采纳"统一入口 + 意图路由"方案，所有输入先分类再分发 |
| 世界模拟通信机制 | 不单独维护 message bus，采用 item 绑定发布机制 |
| 天气管理 | 天气作为全局 item 统一管理，所有角色同步感知 |
| event_info 结构 | 只记录最新状态（state），不含 old_state |
| 角色感知机制 | 第一版采用坐标感知，仅感知当前位置邻近 item 的实时变化 |
| 离开区域后的同步 | 不再自动同步，回归时获取最新状态，不追溯中间过程 |
| 灵魂 Agent vs Deep Feeling | 灵魂 Agent 用于 LBS 世界模拟（推理+反思），Deep Feeling 用于聊天场景 |
