## 一、系统总览

### 1.1 设计目标

让 AI 角色具备**灵魂感**（主体性 + 进化）：
- **有故事**：编剧 Agent 推动剧情，角色活在故事里
- **有主体**：角色通过 Deep Feeling 自主感受、推理、决策，有能力偏离编剧安排的轨道
- **有进化**：角色的情感、关系、认知随经历持续变化

### 1.2 核心组件

| 组件 | 角色 | 类比 |
|------|------|------|
| 时钟 | 驱动一切的心跳 | 时间 |
| 天道 Agent | 世界氛围发生器，输出虚态事件（氛围/运势/趋势） | 大运流年 / 自然法则 |
| 编剧 Agent | 事件执行中枢，将氛围演绎为具体事件 + 角色日程 + 剧情指令 | 编剧 / 导演 |
| 世界模拟 Agent | 物理引擎，维护物品状态，item 绑定发布 | 物理世界 |
| 角色 Agent | 感知、感受、决策、行动的主体 | 人 |

### 1.3 系统拓扑图

> 在线查看（含连线可视化）：[NPC Agent 系统拓扑图](https://aigc-image-1253543992.cos.ap-beijing.myqcloud.com/architecture/npc_agent_topology_20260415_114920.html)

```
  时钟 ──tick──→ 天道 ──氛围信号(虚态)──→ 编剧 ──events(实态)──→ 世界模拟 ──event_info──→ 角色
    │                                    │                        ↑                     ↑↓
    └──tick──────────────────────────→ 世界模拟              角色行为结果              reply
                                        ↑                  用户操作                    ↓
                                        │                                            用户
                                   world_state ──→ 编剧
                                   编剧 ──plot_directive──→ 角色
```

**关键变化（对齐会确认）：天道不再直连世界模拟，天道只输出虚态氛围信号给编剧，由编剧统一演绎为实态事件。**

### 1.4 完整数据流清单

| # | 从 | 到 | 数据 | 说明 |
|---|----|----|------|------|
| 1 | 时钟 | 天道 | `tick` `current_time` | 驱动天道演进 |
| 2 | 时钟 | 世界模拟 | `tick` `current_time` | 驱动机械更新（课表、作息） |
| 3 | 天道 | 编剧 | `atmosphere` | 虚态事件：世界氛围/运势/情绪趋势 |
| ~~4~~ | ~~天道~~ | ~~世界模拟~~ | ~~common_events[]~~ | ~~已取消：天道不再直接修改世界状态~~ |
| 4 | 编剧 | 世界模拟 | `common_events[]` `persona_events[]` | 所有实态事件统一由编剧产出 |
| 5 | 编剧 | 角色 | `plot_directive` | 剧情指令 + 角色日程安排 |
| 6 | 世界模拟 | 编剧 | `world_state` | 当前物品状态，编剧决策依据 |
| 7 | 世界模拟 | 角色 | `event_info[]` | 按角色 item tree 过滤，item 绑定发布 |
| 8 | 角色 | 世界模拟 | `action_results[]` | 行为导致的物品状态变更 |
| 9 | 角色 | 编剧 | `character_state` | 情感/关系/位置/成长 |
| 10 | 用户 | 世界模拟 | `user_input` | 用户直接操作世界 |
| 11 | 用户 | 角色 | `user_message` | 用户跟角色聊天 |
| 12 | 角色 | 用户 | `reply` | 角色回复用户 |

### 1.5 虚态事件 vs 实态事件（对齐会核心结论）

| | 虚态事件 | 实态事件 |
|---|---------|---------|
| 产出者 | 天道 Agent | 编剧 Agent |
| 性质 | 氛围、趋势、运势，不指向具体动作 | 具体行为变更，驱动世界状态变化 |
| 举例 | "今日全城悲伤氛围" | "物理课改体育课" |
| 下游 | → 编剧（作为演绎素材） | → 世界模拟（更新物品状态） |
| 是否改变世界状态 | **否** | **是** |

## 二、各 Agent 详细设计

### 2.1 天道 Agent

**定位：世界氛围发生器。** 独立运行，只输出虚态信号，**不直接修改世界状态**。

```
  tick ────────→┌──────────────┐
  current_time ─→│  天道 Agent   │
                │  (大运流年)    │
                │              │
                │ 内部：        │
                │ · 运势轮转    │
                │ · 情绪场     │
                │ · 氛围趋势   │
                └──────┬───────┘
                       │
                       ▼
                  atmosphere
                (虚态氛围信号)
                       │
                       ▼
                     编剧
              (由编剧演绎为实态事件)
```

**atmosphere 示例：**
```json
{
  "current_phase": "篮球联赛备战期",
  "world_mood": "紧张、竞争",
  "season": "晚春、多雨",
  "fortune_hint": "今日偏动荡，易生口角",
  "active_trends": ["校际篮球联赛下周开始", "期中考试临近"]
}
```

### 2.2 编剧 Agent

**定位：事件执行中枢。** 接收天道氛围 + 世界/角色状态，统一产出所有实态事件。

```
  天道.atmosphere ───→┐
  world_state ──────→│
  character_states ─→│  编剧 Agent
  user_behavior ────→│  (事件执行中枢)
  plot_progress ────→│
  story_config ─────→│
                     └───┬──────────────┬────────────┐
                         ▼              ▼            ▼
                  common_events    persona_events   plot_directive
                  (世界级实态事件)  (角色相关实态事件) (剧情指令+日程)
                     ↓                ↓               ↓
                  世界模拟          世界模拟           角色
```

**编剧如何演绎天道氛围：**
```
天道输出："今日全城悲伤氛围"
编剧演绎：
  · common_event: "学校广播播放了一首悲伤的音乐"
  · persona_event: "钟辰时收到了一条让他难过的消息"
  · 日程微调: 取消原定的户外活动
```

**plot_directive 包含两类内容：**
1. **日程安排**（默认轨道）：角色今天的日程表，角色可以基于 deepfeeling 偏离
2. **剧情事件**：接下来要发生的剧情内容，角色通过感知获取

**两种模式的差异：**

| | 故事模式 | 日常陪伴模式 |
|---|---------|-----------|
| 世界观 | 角色的世界（南一高中） | 用户的真实世界 |
| 编剧产出 | 推动角色世界故事线的事件 | 角色"那边"发生了什么 |
| 用户角色 | 用户是世界中的参与者 | 用户是"另一个世界的人" |
| 交互方式 | 角色与用户在同一场景 | 聊天、打电话、发消息（异步） |

### 2.3 世界模拟 Agent

**定位：物理引擎 + item 绑定发布。** 不产出事件，只处理状态更新和分发通知。

```
  编剧.common_events[] ───→┐
  编剧.persona_events[] ──→│  世界模拟 Agent
  tick + current_time ─────→│  (物理引擎)
  角色.action_results[] ──→│
  用户.user_input ─────────→│
                            │
                    ┌───────┴────────┐
                    │  全量物品状态树  │
                    │ (item 绑定发布) │
                    └───────┬────────┘
                            │
                 ┌──────────┴──────────┐
                 ▼                     ▼
            world_state           event_info[]
            (世界状态快照)         (按角色 item tree
               ↓                  过滤后分发)
              编剧                    ↓
                                    角色
```

**对齐会确认的设计要点：**
- **item 绑定发布**：不单独维护 message bus，事件通知绑定在 item 上
- **天气作为全局 item**：所有角色同步感知
- **event_info 只记录最新状态**，不含 old_state

**event_info 结构（对齐会修订）：**
```json
{
  "item": "南一高中:教学楼:高二三班教室:钟辰时的书桌",
  "state": "课本散落一地，椅子倒了",
  "cause": "周往路过时不小心撞到",
  "time": "2026-04-15 10:15",
  "related_personas": ["钟辰时", "周往"]
}
```

**全量物品状态树示例：**
```json
{
  "南一高中": {
    "教学楼": {
      "高二三班教室": {
        "钟辰时的书桌": { "state": "整齐摆放着课本和笔记", "owner": "钟辰时" },
        "黑板": { "state": "写着今天的值日表", "owner": null }
      }
    },
    "全局": {
      "天气": { "state": "多云转小雨", "owner": null }
    }
  }
}
```

### 2.4 角色 Agent

感知、感受、决策、行动的主体。详见第三章。

```
  event_info[] ────→┐
  plot_directive ──→│  角色 Agent
  user_message ────→│
                    │  ┌──────────────────────────┐
                    │  │ 感知 → 记忆+情绪 → 分流:   │
                    │  │                           │
                    │  │  Short → 直出按日程         │
                    │  │  Brief → 一行内心，按日程    │
                    │  │  Deep  → 完整推理，可偏离    │
                    │  │                           │
                    │  │ → 执行                     │
                    │  └──────────────────────────┘
                    │
           ┌────────┼────────┐
           ▼        ▼        ▼
    action_results  reply  character_state
      ↓               ↓        ↓
    世界模拟          用户      编剧
```

## 三、角色 Agent 内部架构

### 3.1 设计原则

1. **角色是"活人"**：主动感知环境，不是被动接收通知
2. **记忆和情绪是两套独立系统**：记忆 = 经历了什么；情绪 = 当下的感受（VAD）
3. **用 Deep Feeling 替代论文的反思模块**：不只是"想明白了什么"，而是"经历了什么样的内心过程"
4. **编剧给默认轨道，角色保留主体性**：日程由编剧安排，角色可以基于 deepfeeling 偏离
5. **偏离 = 主体性的体现**：灵魂感 = 主体性 + 进化

### 3.2 三种模式：Short / Brief / Deep

角色不是对所有感知都做深度推理。大部分时候直接按日程执行，不需要任何内心戏。

| 模式 | 触发条件 | 做什么 | 占比 | 举例 |
|------|---------|--------|------|------|
| **Short** | 日常琐事，无情感波动 | 不推理，直接按日程执行 | ~80% | 上课铃响→去上课 |
| **Brief** | 轻微情感触动 | 简短推理，一行内心，不改变行为 | ~15% | 看到周往打球→"又在练球了" |
| **Deep** | 强烈情感冲击 | 完整推理+反思+多方案权衡，可能偏离日程 | ~5% | 周往受伤→挣扎→偏离日程去看他 |

**只有 Deep 模式才可能触发日程偏离。**

### 3.3 感知机制（对齐会确认）

**坐标感知：** 第一版采用坐标感知机制，角色仅能感知当前位置邻近物品的实时变化。

**认知状态树：** 每个角色拥有专属认知状态树（= item tree），初始仅知晓自身周围环境。认知范围随交互逐步扩展。

**关键规则：**
- 离开区域后，**不再自动同步**该区域的状态变更
- 回归时获取最新状态，**不追溯中间过程**
- 通过与其他角色交流可获取未知区域信息（认知扩展）

### 3.4 内部流程

```
  感知到的所有信息
  (坐标邻近的 item 状态变化 + 日程 + 剧情 + 其他角色 + 用户消息)
         │
         ▼
  ┌──────────────────────────────────┐
  │  记忆 Memory  │◄─互相影响─►│ 情绪 VAD │
  └──────┬────────┘            └────┬─────┘
         └────────────┬─────────────┘
                      ▼
              intent_skill
            意图 + 情感强度判断
                      │
         ┌────────────┼────────────┐
         ▼            ▼            ▼
     ┌───────┐   ┌────────┐   ┌────────┐
     │ Short │   │ Brief  │   │  Deep  │
     │不推理  │   │一行内心  │   │完整推理 │
     │直出    │   │VAD微调  │   │+反思   │
     │按日程  │   │按日程   │   │可偏离  │
     └───┬───┘   └───┬────┘   └───┬────┘
         └───────────┴────────────┘
                     │
                     ▼
                   执行
          ┌────────┼────────┐
          ▼        ▼        ▼
   action_results reply  char_state
     → 世界模拟    → 用户   → 编剧
```

### 3.5 每 tick 循环

```
每个 tick：

1. 感知（Perceive）
   坐标感知：扫描当前位置邻近 item 的状态变化
   同时获取：日程、剧情内容、其他角色、用户消息、环境

2. 记忆 + 情绪更新
   感知内容写入记忆流，同步更新 VAD

3. 模式分流（intent_skill）
   · 无情感波动 → Short：跳过推理，直接按日程执行
   · 轻微触动   → Brief：简短推理，一行内心，按日程执行
   · 强烈冲击   → Deep：完整推理 + 反思 + 多方案权衡

4. 执行（Execute）
   Short / Brief → 按日程执行
   Deep + 强情感 → 可能偏离日程（偏离 = 主体性）

5. 异步更新
   emotion_update → 写入新 VAD
   memory_write → 写入记忆摘要
```

### 3.6 与斯坦福小镇论文的关键差异

| 环节 | 论文（斯坦福小镇） | 我们的设计 |
|------|-----------------|----------|
| 感知 | pull，扫描附近 tile 的 events | **坐标感知**，离开不同步，回归刷新，不追溯中间过程 |
| 记忆 | 记忆流（观察/反思/计划，8字段），是唯一系统 | **保留记忆流，但与情绪分离为两套独立系统** |
| 情绪 | 没有 | **新增 VAD 情绪系统**，独立存储，与记忆互相影响 |
| 推理/反思 | 简单 LLM 推理 + 重要性>150 触发反思 | **替换为 Deep Feeling**（Short/Brief/Deep 三模式） |
| 规划 | 角色自主三级规划（粗→小时→执行级） | **日程由编剧安排**，角色感知日程作为默认轨道 |
| 主体性 | 完全自主（但缺乏叙事控制） | **编剧给轨道 + 角色可偏离**，偏离由 deepfeeling 驱动 |

### 3.7 记忆系统（参考论文）

**单条记忆 8 字段（与论文一致）：** 记忆ID、自然语言描述、类型（观察/反思/计划）、创建时间戳、最近访问时间戳、重要性分数（1-10）、引用指针列表、嵌入向量

**三维检索：** Final Score = Normalized(Recency) + Normalized(Importance) + Normalized(Relevance)

### 3.8 情绪系统（新增）

独立于记忆，用 **VAD 模型**表示角色当下情绪：V(愉悦度) / A(激活度) / D(支配感)，范围 -1~1。感知时同步更新，随时间自然衰减回基线。

### 3.9 角色 Item Tree（= 认知状态树）

每个角色的认知子集，初始仅包含角色知晓的区域。世界模拟据此过滤 event_info。可通过感知和交流动态扩展。

```json
{
  "南一高中": {
    "教学楼": {
      "高二三班教室": ["钟辰时的书桌", "黑板", "讲台"],
      "学生会办公室": ["会议桌", "文件柜", "钟辰时的储物格"]
    },
    "图书馆": { "阅览室": ["靠窗的老位置"] }
  }
}
```

### 3.10 三种模式决策示例

**Short — 直出**
```
感知：上课铃响了 → 情感强度 0.1 → Short → 按日程去上课，无内心活动
```

**Brief — 一行内心**
```
感知：路过操场看到周往练球 → 情感强度 0.3 → Brief
内心：又在练球了……  VAD: V+0.05
按日程继续走
```

**Deep — 完整推理 + 可能偏离**
```
感知：周往在操场受伤了 → 情感强度 0.9 → Deep

信息装载：memory(上周也扭过脚) + emotion(当前正常) + relationship(好友,亲密度65)
reasoning：他伤得重不重？我应该过去看看
reflection：
  方案A：按日程上课 → 但我会一直担心
  方案B：先过去看看 → 虽然迟到但放不下 → 选B

内心OS：……操场那边好像出事了。是周往？
        不行，先过去看看。课可以迟到，但如果他真伤了……

VAD: V-0.35, A+0.4, D-0.3
执行：偏离日程，去操场（偏离 = 主体性）
→ action_results: 钟辰时离开教室前往操场
→ character_state: VAD变化 + 位置变更 → 反馈给编剧
```

| 决策项 | 结论 |

| 天道 vs 编剧职责 | 天道 = 世界氛围发生器（虚态），编剧 = 事件执行中枢（实态） |
| 天道是否直连世界模拟 | **否**，天道只连编剧，由编剧统一演绎为实态事件 |
| 统一入口 | 采纳"统一入口 + 意图路由"方案，所有输入先分类再分发 |
| 世界模拟通信机制 | 不单独维护 message bus，采用 item 绑定发布机制 |
| 天气管理 | 天气作为全局 item 统一管理，所有角色同步感知 |
| event_info 结构 | 只记录最新状态（state），不含 old_state |
| 角色感知机制 | 第一版采用坐标感知，仅感知当前位置邻近 item 的实时变化 |
| 离开区域后的同步 | 不再自动同步，回归时获取最新状态，不追溯中间过程 |
